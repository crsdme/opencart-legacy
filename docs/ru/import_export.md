# Import / Export

Каталог CSV/JSON: товары, категории, производители, группы характеристик и атрибуты. Это не SQL-дамп **Система → Резервное копирование**.

## Установка

1. Файлы уже в проекте.
2. Админка → Дополнения → Дополнения → Модули → Import / Export → Установить.
3. Откройте **Import / Export** в левом меню (или форму модуля).
4. Выдайте `access` / `modify` для:
   - `extension/module/import_export`
   - `extension/import_export`

Деинсталл **не** дропает историю заданий, пока не включён **Delete job history on uninstall**. Строки каталога никогда не удаляются.

## Как задавать ID

OpenCart сам выдаёт живые id. Не выдумывайте `12` или `7`. Неверный положительный id обновит чужую строку или упадёт с ошибкой.

| Значение | Свой id (`product_id`, `category_id`, …) | Связи (`parent_id`, `category_ids`, `manufacturer_id`, `attribute_id`, …) |
|---|---|---|
| **нет поля** | Создать или обновить, если SKU / имя / путь уже есть | Связь не трогать (при обновлении оставить как было) |
| **`0`** | Всегда **создать** (не искать по SKU / имени) | Корень / нет (`parent_id: 0`, без производителя) |
| **`> 0`** | **Обновить** эту строку магазина. Нет id = ошибка | Должен уже быть в магазине |
| **`< 0`** (`-1`, `-2`) | **Создать** и запомнить число **внутри этого файла** | Ссылка на другую новую строку того же импорта с тем же числом |

Preview показывает Create vs Update до записи. Если строка Update, а вы хотели Create — id живой (или SKU уже есть и id не указали). Поставьте `0` или отрицательный алиас.

### Категория и товар в одном заходе

Нужен **JSON-бандл**, чтобы обе сущности были в одном файле. Берите свободные отрицательные числа; в БД они не сохраняются.

```json
{
  "version": 1,
  "entities": {
    "categories": [
      {
        "category_id": -1,
        "parent_id": 0,
        "name": { "uk": "Футболки", "en": "T-shirts" }
      },
      {
        "category_id": -2,
        "parent_id": -1,
        "name": { "uk": "Чоловічі", "en": "Men" }
      }
    ],
    "products": [
      {
        "product_id": 0,
        "sku": "TEE-001",
        "price": 499,
        "category_ids": [-2],
        "name": { "uk": "Футболка", "en": "T-shirt" }
      }
    ]
  }
}
```

`-1` и `-2` должны быть уникальны **внутри сущности** этого файла (`category_id: -1` и `product_id: -1` — разные). После импорта в магазине живые id; экспортируйте снова, если они нужны.

CSV — одна сущность на файл, поэтому локальные алиасы работают для parent/child **категорий** (`parent_id: -1` рядом с `category_id: -1`). CSV товаров не видит категорию из другого файла — берите живые id из экспорта или JSON-бандл.

### Обновление существующих строк

Сначала экспорт. Оставьте положительные id. Меняются только поля, которые есть в файле.

## Для заполнения ИИ

1. Экспортируйте живой каталог, если нужно **привязаться к существующим** строкам. Копируйте эти положительные id.
2. Для **новых** строк за один раз используйте `0` или отрицательные алиасы. Не копируйте живые id на новые строки.
3. Имена, пути и строки `group` в экспорте — подписи. При записи побеждают ID.
4. Товар к существующим категориям: `category_ids: [12, 15]` и `attributes: [{ "attribute_id": 7, "text": { "uk": "Чорний" } }]`.

Типовые циклы:

- Новое дерево: JSON-бандл с отрицательными id → импорт → экспорт, если потом нужны живые id.
- Новые товары в существующих категориях: экспорт категорий → скопировать `category_id` → импорт товаров.

## Процесс

1. **Шаблоны** — пустой CSV/JSON по живой схеме (колонки id есть). В шаблоне `0` значит создать.
2. Заполнить строки (или взять из **экспорта**, чтобы id были живые).
3. **Импорт** — preview (create / update / skip / error), затем подтверждение.
4. **Экспорт** — та же форма, с id магазина и подписями.

JSON может быть одной сущностью или **бандлом** (`entities`: производители, группы атрибутов, атрибуты, категории, товары). Порядок импорта всегда такой. Категории с локальным `parent_id` сортируются так, чтобы родители создались первыми.

Локализованные ключи (`name.uk`, `name.ru`, …) следуют **включённым** языкам в **Система → Локализация → Языки**. После добавления языка скачайте шаблон снова — старые файлы всё равно импортируются; новый язык копирует дефолт, пока не заполните.

## Идентичность

| Сущность | Ключ обновления | Создание | Связи |
|---|---|---|---|
| Товар | `product_id`, иначе `sku` (или `model`), если id нет | `0` / отрицательный / нет id + `sku` | `manufacturer_id`, `category_ids`, `attributes[].attribute_id` |
| Категория | `category_id` | `0` / отрицательный / нет id + `name` | `parent_id` (`0` = корень, отрицательный = новый родитель в этом файле) |
| Производитель | `manufacturer_id` | `0` / отрицательный / нет id + `name` | — |
| Группа атрибутов | `attribute_group_id` | `0` / отрицательный / нет id + `name` | — |
| Атрибут | `attribute_id` | `0` / отрицательный / нет id + `name` | `attribute_group_id` |

Имя / путь / `group` остаются запасным ключом, когда id **нет**. Отсутствующие ссылки по имени зависят от настройки: **создать**, **ошибка** или **пропустить**. Неизвестные **положительные** id и неизвестные **отрицательные** алиасы (ни на одной строке файла) всегда ошибка.

## Форматы

**JSON:** скачанные шаблоны кладут строку `help` рядом с `version` (id, preview, картинки). Импорт её игнорирует.

```json
{
  "version": 1,
  "help": "Preview first. Live positive ids update that row. 0 = create. Negative ids (-1, -2) create and let other rows in this file link to them (JSON bundle for category + product). Images: local image/catalog path, or http(s) URL to download.",
  "entities": {
    "products": [{
      "product_id": 0,
      "sku": "TEE-001",
      "price": 499,
      "manufacturer_id": 1,
      "category_ids": [12],
      "image": "https://example.com/tee-001.jpg",
      "name": { "uk": "Футболка", "en": "T-shirt" },
      "attributes": [{ "attribute_id": 7, "text": { "uk": "Чорний", "en": "Black" } }]
    }]
  }
}
```

Экспорт также даёт подписи (`manufacturer`, пути `categories`, `name` атрибута), чтобы модель видела, что такое `12` и `7`.

**CSV** — одна сущность на файл. Шаблоны начинаются с комментария `#` (тот же help). Сначала колонки id. Локали — `name.uk`. `category_ids` через `|` (`12|15` или `-1|-2`). `attributes` — JSON-ячейка с `attribute_id`.

Картинки: локальные пути `image/catalog/...` или `http(s)` URL (строка, список или `{ "url": "..." }`). Удалённые файлы качаются при импорте в `image/catalog/import/`. JPEG, PNG, GIF и WebP, максимум 16 МБ. Ссылки Cloudflare `/cdn-cgi/image/...` по возможности разворачиваются к оригиналу. Пустые `image` / `images` пропускаются — импортёр не выдумает фото, которых нет в файле. Неудачная загрузка пропускает картинку; причина в `system/storage/logs/error.log`. Выключите это в **Настройках**, если нужны только локальные пути.

Запись идёт через админские модели `add*` / `edit*` (SEO URL, кэш, события FAQ / Redirect Manager).

## CLI

```
php system/cli/import_export.php template product json
php system/cli/import_export.php export bundle json
php system/cli/import_export.php import catalog.json --dry-run
php system/cli/import_export.php import catalog.json
```

Для больших файлов — CLI. Импорт в админке делает preview, затем пишет с диска; каталог не кладётся в PHP-сессию (`oc_session.data` всего 64 КБ).

## База (`DB_PREFIX`)

- `import_export_job` — только история. Ожидающие загрузки лежат в `system/storage/import_export/`.

Не в v1: опции, Excel, удаление строк каталога, которых нет в файле.
